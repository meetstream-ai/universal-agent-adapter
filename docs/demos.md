# Reproducible meeting demos

## Scope acceptance: streaming, switching, tools and interruption

Use an isolated meeting with the host microphone and camera muted. With the project's keys already saved, run:

```sh
uv run --frozen --all-extras --no-extra dev python scripts/voice_acceptance.py \
  --meeting https://meet.google.com/TEST-CODE \
  --report reports/voice-acceptance.json
```

Replace the example meeting link. This command starts its own local bridge and ngrok tunnel. If your ngrok address is already in use, supply `--public-url https://YOUR-TUNNEL --port 8097` for an existing tunnel to that local port; the harness then leaves that tunnel under your control. Admit **Adapter SDK Test** and **SDK Finite Voice Test** when requested. No MIA backend patch or dashboard agent setup is needed. The finite speaker submits each prerecorded utterance as one audio message to avoid packet gaps, using the same “Okay assistant” wake phrase as guided startup; assistant responses still stream. It uses Deepgram to speak real requests into the meeting; a separately configured listener transcribes the assistant's actual audio. The initial ready roundtrip confirms admission before business-tool checks begin.

By default, the test starts on ADK and switches to LangGraph. Add `--runtime adk` to start on LangGraph and switch to ADK, or `--runtime crewai` to start on ADK and switch to CrewAI. Each run switches using the canonical name, switches back, then selects the target again using a speech variant: “a dee kay,” “land graph” or “crew eye.” It also speaks an unknown runtime name and requires a clarification with no reasoning/tool turn and no runtime change.

The ten checks require initial and target runtime lookup/write plus independently heard confirmation, canonical and variant spoken switches on the same bot/session, safe unknown-name handling, cancellation during a delayed lookup, interruption of an audible six-sentence story, a fresh recovery lookup/write, and confirmed owned-resource cleanup. It records raw STT inputs, incremental SDK events and delivered audio chunks, including whether an audio chunk was delivered while generation remained active. A check passes only with positive evidence; exceptions, missing heard speech or incomplete cleanup fail the report and process exit status. The scenario is finite and stops on failure rather than replaying business writes.

All OpenAI environment variables are removed in the test process, and its bridge allows Google-backed runtimes only. Provider, MeetStream and Deepgram usage still applies. Report files are private and excluded from release packages. Ctrl+C stops the scenario and cleans owned resources; it does not mark interrupted acceptance as passed.

`--mode mia` tests the optional hosted MIA custom-function path; that mode returns completed JSON and does not establish incremental external-agent speech. Hosted MIA owns its recognition policy, so that mode excludes the bridge-parser unknown-name check and must not be used to claim that guard. The default external-agent path is the streaming acceptance target.

## Extended single-runtime soak harness

Use a dedicated Google Meet, a controlled test account and synthetic speech. Do not point this harness at a meeting containing real participants. The host’s camera and microphone can remain off. Two owned MeetStream bots are used: the adapter and a fixture speaker. The latter speaks PCM generated by the common TTS stage into the actual meeting; it does not submit a text turn to bypass STT.

**This is an automated test, not the normal assistant.** It creates a second bot named **SDK Test Speaker** that deliberately asks the counting/stop questions once per interruption cycle. The default is one cycle; `--interruptions 10` repeats it ten times. Use **Control + C** to stop. Cancellation marks the report incomplete, stops owned bots and skips video export. For a normal call with no scripted speaker, use the [quickstart](../quickstart.md).

Install the locked all-framework environment, configure `.env`, run `doctor`, and route `PUBLIC_BASE_URL` to **127.0.0.1:8097** for this harness. The regular service defaults to 8080; do not expose a different service already occupying that port. Stop any previous harness before the next run. The harness creates its own temporary application server, checks its public health endpoint before bot creation and removes both owned bots in `finally`. It requires the shared voice configuration and its fixture wake phrase.

```sh
AGENT_RUNTIME=adk AGENT_MODEL=gemini-3.5-flash-lite \
  uv run python scripts/live_meeting_demo.py --env-file .env \
  --config examples/voice-demo.toml --meeting 'https://meet.google.com/TEST-CODE' \
  --output reports/live-voice-adk.json

AGENT_RUNTIME=langgraph MODEL_PROVIDER=google AGENT_MODEL=gemini-3.5-flash-lite \
  uv run python scripts/live_meeting_demo.py --env-file .env \
  --config examples/voice-demo.toml --meeting 'https://meet.google.com/TEST-CODE' \
  --output reports/live-voice-langgraph.json
```

Admit **Adapter SDK Test** and **SDK Test Speaker** promptly when requested. Enable captions and open meeting chat to observe delivery. A brief low-level test tone primes the fixture virtual microphone before its first wake phrase (`Okay assistant`, configured in the shared demo profile). The first spoken request names the action fields explicitly (`title verify and owner Alex`) and asks for project status. The report requires both tools, exactly one write with those argument values, at least two public deltas, audio and chat. The next request asks for every number from one through one hundred; a third spoken request interrupts it. A short/refused answer or finished local playback cannot count as sustained-answer barge-in. The stop baseline is sampled after the count response begins, so the count request's earlier onset is excluded. Capture the evidence window before cleanup. Inspect the final report: cleanup now polls independent terminal bot status. A rejected/lost removal response is resolved only by that state; a successful removal request alone does not establish departure.

The local Deepgram path accumulates final segments and commits at a current `UtteranceEnd` after a 2.5-second gap. It ignores stale `last_word_end=-1` notifications and boundaries older than words already recognized in interim/final results. A short `speech_final` endpoint inside a sentence must not execute a partial request. [Deepgram documents that gap events may arrive while speech continues](https://developers.deepgram.com/docs/utterance-end); gap timing alone cannot guarantee semantic completeness. Input is mixed 48 kHz PCM; dominant-speaker attribution remains approximate. The shared Deepgram speech provider produces 24 kHz PCM, converted to 48 kHz for the MeetStream control channel. The basic sample-hold conversion preserves timing; it is not a high-fidelity resampling implementation.

A faster **paid provider/tool check without a meeting** is available:

```sh
AGENT_RUNTIME=adk AGENT_MODEL=gemini-3.5-flash-lite \
  uv run python scripts/verify_runtime.py --env-file .env --output reports/live-provider-adk.json
AGENT_RUNTIME=langgraph MODEL_PROVIDER=google AGENT_MODEL=gemini-3.5-flash-lite \
  uv run python scripts/verify_runtime.py --env-file .env --output reports/live-provider-langgraph.json
```

Use `meetstream-adapter demo` for a clearly labeled offline fake-runtime example. It is never selected automatically on a live failure. Provider-only checks do not count as voice acceptance. Socket audio submissions are marked `submitted_unconfirmed` because MeetStream offers no per-frame audible playback acknowledgment. Meeting captions provide an independent observation of the spoken output.

Optional in-process native MIA integration additionally requires wiring `NativeMIAOutput` to the actual backend’s speech queue and feeding finalized transcripts/speech-onset events into the same host. The public bridge cannot perform that private backend change through a documented public API.


For release acceptance, add `--interruptions 10 --fault-cases --record-video --soak-seconds 1800` to the meeting harness. It stops on the first failed cycle instead of silently retrying, checks recovery after every interruption and verifies the session remains connected with bounded history/events during the 30-minute soak. Every four minutes it speaks a real ready-check request and verifies fresh runtime completion and submitted speech. This tests the complete voice path and avoids the documented 600-second silent-meeting auto-leave default; it is an active-session soak, not a 30-minute silence test. This is real meeting/provider usage. Keep the host in the test meeting until cleanup.

Additional explicit measurements:

```sh
# Actual native framework runners, controlled model; no provider/network claim.
uv run python scripts/benchmark_native.py --samples 100 --cancellations 10
# Real Gemini provider, no tools/meeting; consumes usage and takes about 27 min.
uv run python scripts/benchmark_provider.py --samples 100 --interval 8
```

The provider benchmark defaults to ADK and CrewAI using the same Gemini model and prompt. Add `--profiles adk langgraph` to sample LangGraph through its explicit native Google integration instead. It reports first-text and whole-turn percentiles, sample counts and configured request spacing. Provider region is not exposed; the client timezone is recorded. Controlled-model measurements include fixture delays and must not be presented as pure adapter overhead. Live reports contain only owned IDs, diagnostics and isolated synthetic test transcripts, never credentials or callback tokens. Keep them out of public release artifacts unless reviewed.

`--fault-cases` additionally delays the actual shared lookup handler and the selected speech provider by eight seconds, one case at a time. A separately spoken stop must cause a new acoustic interruption, cancel the delayed operation cooperatively, complete a fresh stop turn and leave exactly the initial single sandbox write. The original handler/provider is restored before recovery. These are explicit test-only delays; runtime reasoning, STT and TTS still use real services. A run without this flag does not establish slow-tool/delayed-speech acceptance. Admission failures record the last safe adapter/speaker status and terminate early when either bot has already ended.

`--record-video` opts the fixture speaker bot into MeetStream video recording with `speaker_view`; the production adapter remains audio-only. After both owned bots leave, the SDK waits up to ten minutes for the official recording and saves a private MP4 beside the JSON report. Choose a new report name: an existing MP4 is never overwritten. The harness waits for terminal bot status and bounds the observed processing-time 404 race; the SDK also polls normal 202 responses. The download accepts documented HTTPS S3 URLs, uses no model/MeetStream authorization headers, and removes incomplete files. Presigned URLs and provider response bodies are never logged or stored in the report. Record only these isolated synthetic test meetings. See [MeetStream recording retrieval](https://docs.meetstream.ai/guides/transcription-recordings/retrieve-recordings). A requested export failure makes the run fail rather than claiming a complete demo.
